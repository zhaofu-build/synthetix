# 01 - 系统架构概览

## 总体架构

Claude Code 采用**六层分层架构**，各层按优先级动态组装，形成完整的系统运行环境。从上到下依次为：入口层 → 协调层 → Agent 层 → 工具层 → 核心引擎层 → 基础设施层。

核心设计哲学：**分层解耦、优先级覆盖、动态组装**。

## 六层架构详解

### 1. 入口层（优先级 1）

系统启动入口，负责初始化环境和配置。

**核心文件：**
- `main.tsx`：启动 Bun 运行时并初始化 React Ink 终端 UI
- `setup.ts`：配置环境变量、加载用户设置、初始化安全机制
- CLI 参数处理：解析 `--permission-mode`、`--allowedTools` 等启动参数

**技术亮点 — 并行预取优化：**

启动前 19 行代码并行加载关键依赖（MDM 设置、钥匙串、遥测系统），启动时间优化约 40%。这体现了"并行优于串行"的工程原则。

### 2. 协调层（优先级 2）

多智能体协作核心，采用 **Cooperator-Worker 模式**。

**核心组件：**
- `AgentTeamsController.ts`：管理 Agent Teams 的创建、协调和通信
- `/permissions` 命令：处理权限依赖关系，支持计划审批模式和委托模式
- `Mailbox` 消息系统：Agent 间点对点通信，支持进程内、分屏和自动模式

**启用方式：** 通过 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 环境变量启用多 Agent 协作架构。

**技术亮点：** 文件锁机制管理任务依赖，确保并行执行的正确性和一致性。复杂开发任务处理效率提升 3 倍以上。

### 3. Agent 层（优先级 3）

核心执行单元。

**核心组件：**
- `AgentTool.ts`：子 Agent 生成工具，支持独立沙箱环境运行
- `AgentLoop.ts`：实现 TAOR 循环（Think → Act → Observe → Repeat）的运行时
- `BuddySystem.ts`：终端电子宠物系统（18 种物种、6 种稀有度，由账户 ID 唯一生成）

**技术亮点 — 统一入口设计：** 所有 Agent 通过 `AgentBase` 抽象类实现，确保接口一致性和可扩展性。

### 4. 工具层（优先级 4）

Claude Code 能力的根基，包含 40+ 内置工具和 40+ 斜杠命令。

**核心设计：**
- `Tool.ts`：定义 `ToolBase` 抽象类接口，强制实现 `execute` 方法
- 具体工具（`BashTool.ts`、`FileEditTool.ts` 等）：每个工具通过 **Zod v4** 定义 Schema 校验
- `MCPTool.ts`：实现 MCP 协议，连接外部工具服务器

**技术亮点 — 标准化接口设计：** 类似 Unix 哲学，"每个工具都做好一件事"。通过 `@anthropic/mcp-connectors` 库统一接入，极大提升可维护性和扩展性。

### 5. 核心引擎层（优先级 5）

系统"心脏"，`QueryEngine.ts` 约 **4.6 万行代码**。

**核心方法：**
- `runTAORLoop`：TAOR 循环核心逻辑（Think → Act → Observe → Repeat）
- `getSystemPrompt`：动态组装系统提示词，结合静态前缀和动态后缀
- `snipCompression`：五级上下文压缩核心算法，保留语义连续性

**技术亮点 — 动态 Prompt 组装：** 通过分层缓存优化，使同一用户在不同项目中获得不同的"AI 助手人格"。`snipCompression` 算法在对话变长时自动截断历史消息但保留语义关键点，解决上下文窗口限制。

### 6. 基础设施层（优先级 6）

底层支持。

**核心能力：**
- **认证系统**：OAuth、JWT 身份验证
- **存储与缓存**：记忆系统持久化存储和高速访问
- **远程控制**：200+ 远程开关，支持服务端实时推送配置和功能禁用

## 核心目录结构

```
src/
├── cli/              # 命令行界面实现
├── core/
│   ├── queryEngine/  # 核心查询引擎（~4.6 万行）
│   └── context/      # 上下文管理（~1729 行）
├── tools/            # 40+ 内置工具
├── plugin/           # 插件系统实现
├── prompt-engine/    # 提示词工程模块
└── mcp/              # MCP 协议实现
```

**数据流：** 用户输入 → 入口层 → 协调层（任务拆分） → Agent 层（TAOR 循环） → 工具层（执行） → 核心引擎层（上下文更新） → 基础设施层（持久化）

## 配置优先级

```
CLI 参数 > 本地设置(.claude/settings.local.json) > 项目设置(.claude/settings.json) > 用户设置(~/.claude/settings.json)
```

**关键规则：** 任何层级的 `deny` 规则具有最高优先级，不会被更高层级的 `allow` 覆盖。这确保了安全策略的不可绕过性。

## 技术栈选型理由

| 技术 | 选型理由 |
|------|----------|
| **Bun** | 高性能 JS/TS 运行时，支持死代码消除（feature flags），比 Node.js 启动更快 |
| **TypeScript 严格模式** | 类型安全 + Zod v4 运行时校验，编译时和运行时双重保障 |
| **React + Ink** | 组件化终端 UI，支持复杂布局和实时更新 |
| **tree-sitter** | 增量解析，支持多语言语法树分析，用于依赖图构建 |
| **Zod v4** | 声明式 Schema 定义，同时生成类型和校验逻辑 |

## 架构特点总结

1. **分层解耦**：六层各司其职，层间通过明确接口交互，支持多种使用场景（CLI、IDE 插件、网页版）
2. **统一抽象**：工具通过 `ToolBase` 统一接口，Agent 通过 `AgentBase` 统一入口，降低系统复杂度
3. **命令系统**：50+ 斜杠命令（/commit、/review 等），通过统一注册机制管理
4. **性能优化**：并行预取、懒加载、死代码消除（Bun feature flags）
5. **插件化设计**：Skills 系统 + Plugin 系统 + IDE 桥接三层扩展
