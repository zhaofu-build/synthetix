# 10 - 代码转换管道

## 概述

代码转换管道将自然语言需求转化为可执行代码的完整流程：**意图解析 → 代码生成 → 验证修正**。这是 Claude Code 的核心功能实现路径，通过提示词工程引导模型输出结构化结果，结合多层验证确保代码质量。

## 流程总览

```
用户输入自然语言需求
  ↓
意图解析（IntentParser）
  ├── 意图分类（7 种类型）
  ├── 参数提取
  └── 优先级排序
  ↓
代码生成（CodeGenerator）
  ├── 选择模板
  ├── 构建提示词
  └── 调用模型生成代码
  ↓
代码验证（多层验证）
  ├── 语法验证
  ├── 风格验证
  ├── 依赖验证
  └── 业务逻辑验证
  ↓
┌─ 验证通过 → 格式化 → 执行 → 输出
│
└─ 验证失败 → 修正循环（最多 3 次）
                ↓
              重新生成 → 重新验证
```

## 1. 意图解析

### 核心实现

```typescript
class IntentParser {
  async parseUserIntent(input: string): Promise<Intent> {
    // 1. 提示词工程进行意图分类
    const classification = await claudeAPI.call(classificationPrompt);

    // 2. 提取参数（语言、框架、依赖等）
    const params = await claudeAPI.call(paramsPrompt);

    // 3. 构建意图对象
    return {
      name: classification.name,
      description: classification.description,
      parameters: params,
      priority: calculatePriority(classification),
      dependencies: params.dependencies,
      requiredTools: classifyRequiredTools(classification)
    };
  }
}
```

### 意图类型

| 类型 | 说明 | 示例用户输入 |
|------|------|-------------|
| `write_code` | 编写新代码 | "写一个 Python 函数实现快速排序" |
| `modify_code` | 修改代码 | "修复这个空指针 bug" |
| `run_code` | 运行代码 | "运行这个脚本" |
| `debug_code` | 调试代码 | "找出这个函数的性能瓶颈" |
| `refactor_code` | 重构代码 | "将这个类重构为函数式风格" |
| `plan_development` | 规划开发 | "规划新功能实现的步骤" |
| `review_code` | 代码审查 | "审查这个组件的安全性" |

### 提示词工程

意图解析的提示词设计关键：

```typescript
const classificationPrompt = `你是一个代码解析专家，请将以下任务解析为 JSON 格式，包含：
- language: 代码语言（如 Python/Java/JavaScript）
- framework: 使用的框架（如 React/Spring）
- dependencies: 需要的依赖项
- requirements: 具体功能需求
- codeStructure: 代码组织结构
- testRequirements: 测试要求

任务: ${task}`;
```

**设计要点：**
- **结构化输出要求**：强制模型输出 JSON 格式，便于后续处理
- **多层验证**：解析后通过 `validateParsedTask` 验证关键字段完整性
- **上下文管理**：解析时结合项目配置和记忆系统，确保符合项目规范
- **错误处理**：解析失败时通过 `Nudge` 机制提示模型重新解析

### 优先级排序

使用信息熵计算意图优先级 — **低熵（高信息密度）** 意图优先处理。这确保了信息量大的任务（如修改代码）优先于信息量小的任务（如运行代码）。

## 2. 代码生成

### 核心流程

```typescript
class CodeGenerator {
  async generateCode(intent: Intent, context: Context): Promise<CodeResult> {
    let currentContext = { ...context, intent };

    // 迭代式代码生成
    while (true) {
      // 1. 选择合适模板
      const template = templateManager.selectTemplate(intent.name, currentContext);

      // 2. 构建代码生成提示词
      const codePrompt = await buildCodePrompt(intent, currentContext);

      // 3. 调用模型生成代码
      const codeResponse = await claudeAPI.call(codePrompt, { model: 'opus' });

      // 4. 解析生成结果
      const { code, toolCalls } = parseCodeResponse(codeResponse);

      // 5. 代码验证
      const validationResults = await validateCode(code, intent);

      // 6. 验证通过则返回
      if (areAllValidationsPassing(validationResults)) {
        return { code, validation: validationResults };
      }

      // 7. 有工具调用则执行并更新上下文
      if (toolCalls.length > 0) {
        const toolResults = await executeToolCalls(toolCalls);
        currentContext = updateContextWithToolResults(currentContext, toolResults);
      } else {
        // 8. 无工具调用但验证不通过，请求模型修改
        const feedbackPrompt = buildFeedbackPrompt(code, validationResults);
        const modifiedCode = await claudeAPI.call(feedbackPrompt, { model: 'sonnet' });
        currentContext = updateContextWithModifiedCode(currentContext, modifiedCode);
      }
    }
  }
}
```

### 生成策略

- **模板选择**：根据意图类型和上下文选择合适的代码模板
- **模型选择**：复杂生成使用 Opus，修正使用 Sonnet（成本优化）
- **迭代生成**：生成 → 验证 → 修正，直到代码通过验证

## 3. 代码验证

### 多层验证机制

```typescript
async function validateCode(code: string, intent: Intent): Promise<ValidationResult[]> {
  const results = [];

  // 1. 语法验证 — 确保代码语法正确
  const syntaxResult = await syntaxValidator.execute({
    code,
    language: intent.language
  });
  results.push(syntaxResult);

  // 2. 风格验证 — 符合项目编码规范
  const styleResult = await styleValidator.execute({
    code,
    configPath: intent.configPath || 'CLAUDE.md'
  });
  results.push(styleResult);

  // 3. 依赖验证 — 检查依赖项可用性
  const dependencyResult = await dependencyValidator.execute({
    dependencies: intent.dependencies,
    projectRoot: intent.projectRoot
  });
  results.push(dependencyResult);

  // 4. 业务逻辑验证 — 是否满足用户需求
  const businessResult = await businessValidator.execute({
    code,
    requirements: intent.requirements
  });
  results.push(businessResult);

  return results;
}
```

### 各层验证说明

| 验证层 | 目的 | 实现方式 |
|--------|------|----------|
| **语法验证** | 确保代码能被解析器接受 | AST 解析、语法检查 |
| **风格验证** | 符合项目编码规范 | ESLint/Prettier/Black 等工具 |
| **依赖验证** | 确保引用的库/模块存在 | package.json/requirements.txt 检查 |
| **业务逻辑验证** | 是否满足用户需求 | 模型评估 + 单元测试 |

## 4. 验证修正循环

```
生成代码 → 验证 → 结果
  ↓               ↓
  ↓         ┌─ 全部通过 → 返回最终代码
  ↓         │
  ↓         └─ 存在失败 → 构建反馈提示词
  ↓                       ↓
  ↓                  调用模型生成修正代码
  ↓                       ↓
  ↓                  重新验证
  ↓                       ↓
  ↓              ┌─ 通过 → 返回
  ↓              └─ 仍失败（< 3次）→ 继续修正
  ↓                       ↓
  └─ 达到最大迭代次数（3次）→ 返回最佳结果 + 警告
```

**最大迭代次数：3 次**

超过 3 次仍验证失败时：
1. 返回验证得分最高的版本
2. 附加警告信息说明未通过的验证项
3. 建议用户手动检查

## 5. 执行验证

通过 Bash 工具在实际环境中执行代码，验证运行结果：

```typescript
async function verifyCodeExecution(code: string, context: Context): Promise<boolean> {
  const result = await bashTool.execute({
    command: buildExecutionCommand(code, context),
    timeout: 30000  // 30秒执行超时
  });

  if (result.status === 'success') {
    return true;
  }

  // 记录错误信息用于修正
  context.lastError = result.stderr;
  return false;
}
```

## 6. 格式化与优化

### 代码格式化

```typescript
async function formatCode(code: string, intent: Intent): Promise<string> {
  // 1. 根据项目配置选择格式化工具
  const formatter = await getFormatter(intent.configPath);

  // 2. 执行格式化
  const formatted = await formatter.execute({
    code,
    language: intent.language
  });

  // 3. 首选工具失败时尝试备选
  if (!formatted.valid) {
    const alternative = await getAlternativeFormatter(formatter);
    return await alternative.execute({ code, language: intent.language });
  }

  return formatted.code;
}
```

**特点：**
- 支持 ESLint、Prettier、Black 等多种格式化工具
- 格式化时结合项目配置，确保风格一致性
- 首选工具失败时自动降级到备选方案
- 使用轻量级验证器快速检查，避免完整编译

### 代码优化

在生成代码后可选执行优化步骤：
- 性能优化建议（识别 N+1 查询、不必要的循环等）
- 可读性优化（命名改进、结构简化）
- 安全性优化（输入验证、错误处理）

## 异步流式处理

整个管道支持 `AsyncGenerator` 流式输出，用户可实时看到进度：

```
"正在分析您的需求..."          ← 意图解析阶段
"生成了初始代码...正在验证..."   ← 代码生成 + 验证阶段
"发现 1 个问题，正在修正..."     ← 修正循环阶段
"代码验证通过...正在执行..."     ← 执行验证阶段
"执行成功！最终代码：..."        ← 完成阶段
```

这种流式反馈机制使用户不会在长时间等待中失去耐心，增强了交互体验。

## 管道设计总结

| 阶段 | 核心技术 | 关键设计 |
|------|----------|----------|
| 意图解析 | 提示词工程 + JSON 结构化输出 | 7 种意图类型，信息熵优先级 |
| 代码生成 | Opus 模型 + 模板系统 | 迭代生成，工具调用辅助 |
| 代码验证 | 多层验证（语法/风格/依赖/业务） | 4 层独立验证 |
| 修正循环 | 反馈提示词 + Sonnet 模型 | 最大 3 次迭代 |
| 执行验证 | Bash 工具 + 实际运行 | 30 秒超时 |
| 格式化 | 多工具支持 + 自动降级 | 项目配置感知 |
