# 07 - 多智能体协作

## 概述

Claude Code 采用 **Orchestrator-Subagents（主从）架构**实现多智能体协作。主 Agent 负责任务拆分和子 Agent 协调，子 Agent 专注于特定子任务的执行。通过 TaskBoard 共享任务看板、加密消息系统和依赖图分析，实现了复杂任务的并行高效处理。

## Orchestrator-Subagents 架构

```
用户 → Team Lead（主会话，Opus 模型）
         ├── Teammate 1（Sonnet 模型，独立上下文）
         ├── Teammate 2（Sonnet 模型，独立上下文）
         └── Teammate 3（Sonnet 模型，独立上下文）
              ↕ TaskBoard（共享任务看板，JSONL）
              ↕ Mailbox（点对点通信）
```

### 模型分工

| 角色 | 模型 | 职责 |
|------|------|------|
| Team Lead | **Opus**（最强模型） | 任务分析、拆分、编排、成果整合 |
| Teammate | **Sonnet**（高效模型） | 具体子任务执行 |

**设计理由：** Opus 擅长复杂推理和任务规划，Sonnet 在执行速度和成本间取得平衡。主从模型分工实现了质量与效率的最优组合。

### 启用方式

通过环境变量 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 启用多 Agent 协作架构。

## Agent 团队创建

```typescript
async function createAgentTeam(task: Task): Promise<void> {
  // 1. 创建团队工作空间
  await fs.mkdirp(`~/.Claude/tasks/${teamName}/`);

  // 2. 初始化 Team Lead（Opus）
  const leader = new Agent({
    mode: 'Opus',
    isLeader: true
  });

  // 3. 创建子 Agent（Sonnet）
  const subAgents = tasks.map((subTask, index) =>
    new Agent({
      mode: 'Sonnet',
      id: `subAgent${index + 1}`,
      context: {
        projectRoot: subTask.projectRoot,
        memory: subTask.memory,
        currentTask: subTask,
        leaderId: leader.id
      }
    })
  );

  // 4. 启动团队通信
  const taskBoard = new TaskBoard({ teamName });

  // 5. 分发任务
  subAgents.forEach(agent => {
    agent.runAgentLoopWithTaskBoard(task, taskBoard);
  });
}
```

## TaskBoard 共享任务看板

TaskBoard 是多 Agent 协作的核心数据结构，基于 JSONL 格式实现持久化存储。

### 核心实现

```typescript
class TaskBoard {
  path = `~/.Claude/tasks/${teamName}/tasks.jsonl`;
  lock = new FileLock(this.path);

  // 添加任务（文件锁保护）
  async addTask(task: SubTask): Promise<void> {
    await this.lock.acquire();
    await fs.appendFile(this.path, JSON.stringify(task) + '\n');
    await this.lock.release();
  }

  // 获取任务
  async getTask(taskId: string): Promise<SubTask | null> {
    await this.lock.acquire();
    const tasks = await fs.readJSONL(this.path);
    await this.lock.release();
    return tasks.find(t => t.taskId === taskId);
  }

  // 更新任务状态
  async updateTaskStatus(taskId: string, status: TaskStatus): Promise<void> {
    await this.lock.acquire();
    // 读取 → 修改 → 写回
    await this.lock.release();
  }
}
```

### 关键特性

| 特性 | 实现 | 作用 |
|------|------|------|
| **JSONL 格式** | 每行一个 JSON 任务对象 | 简单高效，支持追加写入 |
| **文件锁** | `fsolve` 模块实现 | 防止并发写入的竞态条件 |
| **依赖关系** | 任务间 `dependencies` 字段 | 控制执行顺序 |
| **状态管理** | `pending → in_progress → completed` | 跟踪任务进度 |

### 加密消息格式

```typescript
class Agent {
  async sendAgentMessage(recipient: string, message: string): Promise<void> {
    // 1. 构造加密消息
    const encryptedMessage = encryptMessage(
      JSON.stringify({
        sender: this.id,
        recipient: recipient,
        content: message,
        timestamp: Date.now()
      }),
      this.teamKey  // 团队共享密钥
    );

    // 2. 通过 TaskBoard 发送
    await this.taskBoard.addTask({
      type: 'agent_message',
      content: encryptedMessage,
      priority: 2,
      dependencies: [this.id]
    });
  }

  // 接收并处理消息
  async processAgentMessage(message: string): Promise<void> {
    const decrypted = decryptMessage(message, this.teamKey);
    const parsed = JSON.parse(decrypted);
    // 更新上下文并触发新的查询循环
    await this.contextManager.updateContext({
      type: 'agent_message',
      content: parsed.content,
      source: `Agent ${parsed.sender}`
    });
    await this.queryEngine.runAgentLoop(this.currentTask.description);
  }
}
```

### 消息安全

| 机制 | 说明 |
|------|------|
| 团队密钥加密 | 所有消息使用 `teamKey` 加密 |
| 优先级控制 | Agent 消息优先级低于用户输入和工具结果 |
| 依赖标记 | 消息附带发送者依赖信息 |

## 依赖图构建与分析

Claude Code 使用 **tree-sitter** 解析代码语法树，构建任务依赖关系图。

### 依赖图构建

```typescript
async function buildDependencyGraph(projectRoot: string): Promise<DependencyGraph> {
  // 1. 使用 tree-sitter 解析代码语法树
  const CST = await parseProjectWithTreeSitter(projectRoot);

  // 2. 提取代码元素间的依赖关系
  const dependencies = extractCodeDependencies(CST);

  // 3. 构建带权重的有向无环图（DAG）
  const graph = new DependencyGraph();
  for (const file of CST.files) {
    graph.addNode(file.path);
  }
  for (const dep of dependencies) {
    graph.addEdge(dep.from, dep.to, dep.weight);
  }
  return graph;
}
```

### 依赖关系类型与权重

| 依赖类型 | 权重 | 说明 | 示例 |
|----------|------|------|------|
| import | **0.3** | 文件级依赖 | `import { foo } from './bar'` |
| variable access | **0.5** | 变量访问 | `const x = module.config` |
| function invocation | **0.8** | 函数调用 | `module.process(data)` |

权重越高表示耦合越紧密，影响范围越大。

### 拓扑排序与并行分组

```typescript
class TaskScheduler {
  async scheduleTasks(graph: DependencyGraph): Promise<void> {
    // 1. 拓扑排序确定执行顺序
    const sortedTasks = topologicalSort(graph);

    // 2. 按依赖层级分组（同层任务可并行）
    const parallelGroups = this.groupByLayer(sortedTasks);

    // 3. 分配给不同子 Agent
    parallelGroups.forEach((group, index) => {
      group.forEach(task => {
        team.subAgents[index % team.subAgents.length].addTask(task);
      });
    });
  }

  groupByLayer(tasks: Task[]): Task[][] {
    const layers = new Map<number, Task[]>();
    tasks.forEach((task, index) => {
      const layer = this.calculateTaskLayer(task, index);
      if (!layers.has(layer)) layers.set(layer, []);
      layers.get(layer)!.push(task);
    });
    return Array.from(layers.values());
  }
}
```

### 依赖图的应用价值

- **精准识别**项目中的高内聚模块和过度耦合的"上帝类"
- **评估影响范围**：代码修改的潜在影响范围评估
- **生成合规代码**：符合项目架构规范，避免与现有模式冲突

## 协作工作流

完整的多 Agent 协作工作流：

```
1. 任务拆解
   Team Lead 分析需求 → buildDependencyGraph() → topologicalSort()
   ↓
2. 任务分配
   按依赖层级分组 → 分配给不同 Teammate
   ↓
3. 并行执行
   Teammates 独立运行 TAOR 循环 → 通过 Mailbox 保持联系
   ↓
4. 成果整合
   Team Lead 收集各 Teammate 成果 → 合并检查冲突
   ↓
5. 验收迭代
   根据反馈协调修改 → 直至验收
```

## 安全设计

| 机制 | 实现 | 安全效果 |
|------|------|----------|
| **任务 ID 加密** | 8 位随机前缀 + 分类标识，熵值 41 位 | 防止暴力破解任务 ID |
| **文件锁** | `fsolve` 模块 | 防止竞态条件 |
| **上下文隔离** | 子 Agent 不继承主 Agent 对话历史 | 防止信息泄露 |
| **沙箱执行** | 每个子 Agent 独立沙箱环境 | 防止相互干扰 |
| **消息加密** | `teamKey` 加密所有通信 | 防止消息窃听 |
| **独立记忆** | 子 Agent 拥有独立记忆空间 | 防止上下文污染 |

## 效率提升

多 Agent 协作架构通过**任务并行**和**模型分工**，使复杂开发任务的处理效率提升 **3 倍以上**。依赖图分析确保子任务间的依赖关系被正确处理，避免并行执行时的冲突。
