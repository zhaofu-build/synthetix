# 素材获取渠道分析与扩展方案

## 一、现有渠道

| 渠道 | 类型 | API | 状态 | 说明 |
|------|------|-----|------|------|
| **Pexels** | 免费素材库 | REST API | ✅ 已接入 | 主要渠道，支持搜索+预览+下载，返回双URL（高清下载+SD预览） |
| **Pixabay** | 免费素材库 | REST API | ⚠️ 代码存在但未接入搜索 | `search_videos_pixabay()` 已实现，但前端仅显示 Pexels 结果 |
| **yt-dlp** | 通用视频下载 | 无（库调用） | ✅ 已接入 | 支持上千网站（YouTube/Bilibili等），用于 URL 下载功能 |
| **本地文件** | 文件上传 | 无 | ✅ 已接入 | 支持拖拽上传、批量上传 |

### 现有流程

```
用户输入关键词 → search_videos_pexels() → 返回结果列表（含预览缩略图）
     ↓ 点击"添加"
download_online() → POST /api/videos/download → yt-dlp 或直接下载 → 入库

用户粘贴 URL → downloadVideo() → POST /api/videos/download → yt-dlp 解析下载 → 入库
```

### 关键限制

- Pexels API 限制：200 请求/小时，20,000 请求/月
- Pixabay 已有代码但 `search_online` 端点只调用 `search_videos_pexels()`
- 无音频素材搜索（BGM 仅支持本地库）
- 无图片素材搜索

## 六、P0 实施建议：Pixabay 接入搜索

当前 `search_videos_pexels()` 已有双 URL（下载+预览）模式。`search_videos_pixabay()` 已存在但存在以下问题：

1. 未被 `search_online` API 调用
2. 未返回 `preview_url`（仅返回单一 `url`）
3. 未返回缩略图 `image`
4. 未传递搜索词作为 `tags`

**建议改造方案**：

```python
# video_downloader_adapter.py

def search_videos(search_term: str, minimum_duration: int = 3, source: str = None):
    """统一搜索入口，根据配置或指定 source 选择渠道"""
    source = source or config.video_type
    
    if source == 'pixabay':
        results = search_videos_pixabay(search_term, minimum_duration)
    else:
        results = search_videos_pexels(search_term, minimum_duration)
    
    return results
```

前端可增加渠道选择下拉框（Pexels / Pixabay / 全部），或默认同时搜索两个渠道合并结果（去重）。
