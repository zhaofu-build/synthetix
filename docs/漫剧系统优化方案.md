# 漫剧生成系统优化方案

## 一、现状分析

### 数据模型

单表 `comic_projects`，所有内容存储在 JSON 列中：

```
comic_projects (单行 = 单集)
├── script_data (JSON)    — 脚本结构
├── characters (JSON)     — 角色列表（仅本项目）
├── panels (JSON)         — 所有分镜
├── bgm_config (JSON)     — BGM 配置
└── output_videos (JSON)  — 输出视频
```

### 6 步流水线

| 步骤 | 功能 | 问题 |
|------|------|------|
| 0 脚本 | AI 生成完整脚本 JSON | 没有总时长目标，分镜数量是硬编码的 3-50 |
| 1 角色 | 手动编辑角色属性 | 角色仅存于当前项目，无法跨集复用 |
| 2 分镜 | 编辑分镜 + 逐帧生成图片 | 只生成图片，**不生成视频**（`comic_generate_video` 工具存在但未接入） |
| 3 音频 | 逐对白生成 TTS | 没有角色→音色绑定，每次手动选 |
| 4 BGM | 选择 BGM + 音量 | 只有音量控制，没有淡入淡出 |
| 5 合成 | FFmpeg 图片幻灯片拼接 | **只支持图片幻灯片**，转场未实现，字幕未叠加，音频未混合 |

### 核心缺陷清单

| # | 缺陷 | 影响 |
|---|------|------|
| 1 | **无多集支持** | 做不了连续剧，每集都是独立项目 |
| 2 | **无时长控制** | 不能指定"一集 3 分钟"，分镜数和单帧时长需要手动凑 |
| 3 | **角色不跨集** | 每个项目独立管理角色，多集需要重复建 |
| 4 | **合成只是图片幻灯片** | `generated_video_path` 字段存在但合成管线完全忽略 |
| 5 | **转场未实现** | 数据模型有 transition 字段 (cut/fade/dissolve)，合成代码是硬编码 concat |
| 6 | **字幕未叠加** | 对白文本不渲染到画面上 |
| 7 | **配音未混合** | TTS 音频生成了但合成时没混合进去 |
| 8 | **角色无参考图** | CharacterDef 有 reference_image 字段但前端没有上传 UI |

## 二、优化方案

### 方案 1：多集支持（架构变更）

#### 数据模型变更

引入"系列"概念，一个系列包含多集：

```
comic_series（新表）             — 漫剧系列（如"星际冒险"）
├── id
├── name                        — 系列名称
├── description                 — 系列简介
├── style                       — 画风（所有集共用）
├── genre                       — 类型
├── characters (JSON)           — 共享角色库
├── bgm_config (JSON)           — 系列默认 BGM
└── created_at / updated_at

comic_episodes（新表，原 comic_projects 改造）
├── id
├── series_id (FK)              — 所属系列
├── episode_number              — 集号 (1, 2, 3...)
├── name                        — 集名
├── target_duration             — 目标时长（秒）
├── status
├── script_data (JSON)
├── panels (JSON)
├── bgm_config (JSON)           — 本集 BGM（可覆盖系列默认）
├── audio_config (JSON)
├── current_step
├── output_videos (JSON)
└── created_at / updated_at

comic_characters（新表，全局角色库）
├── id
├── name
├── appearance
├── personality
├── voice_description
├── reference_image
├── voice_id
├── series_id (FK, nullable)    — 绑定系列（空=全局）
└── created_at
```

### 方案 2：时长控制

#### 脚本生成改造

当前 `GenerateScriptRequest` 只有 `num_panels`，没有目标时长。改为：

```python
class GenerateScriptRequest(BaseModel):
    description: str
    genre: Optional[str] = "drama"
    target_duration: float = Field(default=60, ge=10, le=600, description="目标时长（秒）")
    num_panels: Optional[int] = Field(default=None, ge=3, le=100, description="分镜数量（可选，不传则自动计算）")
    characters: Optional[List[Dict]] = None
```

LLM Prompt 增加时长约束：

```
目标总时长: {target_duration} 秒
请根据目标时长自动计算分镜数量和每个分镜的持续时间。
每帧建议 2-5 秒，对白多的场景可适当延长。
```

当用户指定 `target_duration` 但不传 `num_panels` 时，按平均每帧 3 秒自动计算 `num_panels = target_duration / 3`。

#### 前端 UI

脚本生成表单增加：

```
目标时长: [====60====] 秒  （滑块 10-600 秒，或输入"3分钟"）
分镜数量: [自动] / [手动]  （自动时根据时长推算，手动时 3-100）
```

### 方案 3：角色跨集复用

通过方案 1 的 `comic_characters` 表实现。关键行为：

1. **系列级角色库** — 角色绑定到系列，系列内所有集自动可用
2. **角色引用方式** — 面板中 `characters[]` 从字符串名改为角色 ID 引用
3. **角色参考图** — 添加图片上传 UI，用于 AI 图片生成时注入角色外观一致性
4. **角色音色绑定** — `voice_id` 关联到 TTS 音色列表，音频步骤自动匹配

面板引用变更：

```json
// 旧：字符串引用
{ "characters": ["张三", "李四"], "dialogues": [{"character_id": "张三", "text": "..."}] }

// 新：ID 引用
{ "character_ids": [5, 8], "dialogues": [{"character_id": 5, "text": "..."}] }
```

### 方案 5：合成管线升级

当前 `ComicComposer` 只是图片幻灯片。升级为完整管线：

#### 5.1 混合模式

```
对每个分镜面板:
  if generated_video_path 存在:
    → 直接使用视频片段（可能含 AI 运动效果）
  elif generated_image_path 存在:
    → 图片 + Ken Burns 效果（缓慢缩放/平移，避免静态死板）

最终合成:
  视频片段序列
  + 转场效果（fade/dissolve/wipe/zoom，根据 panel.transition）
  + TTS 配音音轨混合
  + BGM 混合（音量控制 + 淡入淡出）
  + 字幕叠加（对白文本渲染到画面底部）
```

#### 5.2 Ken Burns 效果（图片动态化）

对纯图片分镜，用 FFmpeg zoompan 滤镜实现缓慢运动：

```
ffmpeg -loop 1 -i image.jpg -vf "zoompan=z='min(zoom+0.001,1.5)':d=75:s=1280x720" -t 3 output.mp4
```

根据分镜 `camera` 字段选择运动方式：
- `特写` → 缓慢放大
- `远景` → 缓慢缩小
- `全景` → 水平平移
- 无 → 轻微缩放

#### 5.3 转场效果

使用 FFmpeg xfade 滤镜实现分镜间转场：

```python
transition_filters = {
    "fade":      "xfade=transition=fade:duration=0.5:offset={t}",
    "dissolve":  "xfade=transition=dissolve:duration=0.5:offset={t}",
    "wipe":      "xfade=transition=wipeleft:duration=0.5:offset={t}",
    "zoom":      "xfade=transition=zoom_in:duration=0.5:offset={t}",
    "cut":       None,  # 直接拼接
}
```

#### 5.4 音频混合

```python
# 1. 先合成视频轨道（含转场）
# 2. 创建空白音频轨道
# 3. 按时间轴叠加各分镜的 TTS 配音
# 4. 混合 BGM（音量 + fade_in/fade_out）
# 5. 最终输出
```

#### 5.5 字幕叠加

将对话文本渲染为 ASS/SRT 字幕叠加到画面：

```python
# 从 panels 提取所有对白，生成 SRT
for panel in panels:
    start = cumulative_time
    end = start + panel["duration"]
    for dlg in panel.get("dialogues", []):
        srt_entry = f"{idx}\n{_srt_time(start)} --> {_srt_time(end)}\n{dlg['text']}\n"
```

## 三、实施优先级

| 阶段 | 内容 | 影响 |
|------|------|------|
| **P0 — 合成管线** | 视频片段支持、Ken Burns 效果、转场、音频混合、字幕叠加 | 直接提升输出质量 |
| **P1 — 分镜视频** | 前端接入 `generate-video` API、单独重生成按钮 | 从静态图片进化到动态视频 |
| **P2 — 时长控制** | `target_duration` 参数、LLM 自动计算分镜 | 精准控制每集时长 |
| **P3 — 多集 + 角色库** | series 表、全局角色、ID 引用 | 连续剧创作能力 |
| **P4 — 角色参考图** | 上传/AI生成参考图、注入图片生成 prompt | 角色视觉一致性 |

P0 + P1 可以在不改数据模型的情况下完成（利用现有 `generated_video_path` 字段和 `transition` 字段），投入产出比最高。

## 四、关键技术细节

### 4.1 不改表结构能做多少？

现有 `StoryboardPanel` 模型已有：
- `generated_video_path` — 视频路径
- `transition` — 转场类型
- `camera` — 镜头运动
- `dialogues` — 对白（可用于字幕）
- `generated_audio_paths` — TTS 音频

所有 P0 + P1 需要的数据字段都已存在，只需要升级 `ComicComposer` 和暴露前端 API。

### 4.2 FFmpeg 性能考虑

- Ken Burns (zoompan) CPU 密集，每个 3 秒帧需要约 72 帧 × 1280×720 的缩放计算
- xfade 转场需要同时解码两个视频段
- 大量分镜时建议先用临时文件逐段处理，最后 concat demuxer 拼接（避免 filter_complex 过长）

### 4.3 数据迁移

如果实施 P3（多集支持），需要：
1. 创建 `comic_series` 和 `comic_characters` 表
2. 将现有 `comic_projects` 迁移为 `comic_episodes`，自动为每个项目创建一个单集系列
3. 提取 `characters` JSON 到 `comic_characters` 表
4. 面板中的字符串引用改为 ID 引用
