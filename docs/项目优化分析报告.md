## 一、安全问题（P0-P1）

### 1.1 API Key 明文泄露风险 [P0]

- **文件**: `.env` 第 12 行
- **问题**: Pexels API Key 明文写在 `.env` 中，且硬编码路径 `D:/hf-model`（`main.py:9-15`、`src/shared/constants.py:173`）
- **建议**:
  1. 立即轮换已暴露的 API Key
  2. 检查 Git 历史 `git log --all -- .env` 确认是否曾被提交
  3. 将 `MODEL_CACHE_DIR` 默认路径改为 `os.path.join(os.path.expanduser('~'), '.cache', 'hf-model')`

### 1.2 无 API 认证机制 [P0]

- **文件**: `src/interfaces/api/` 下所有路由
- **问题**: 所有 API 无任何认证，包括 `/api/agent/execute`（直接执行任意工具）、`/api/nexus`（代理 LLM 调用消耗 API Key）等敏感接口
- **建议**: 至少添加 API Key 认证中间件；`/api/agent/execute` 限制可调用工具白名单

### 1.3 CORS 配置过于宽松 [P0]

- **文件**: `.env:15`、`main.py:157-163`
- **问题**: `CORS_ORIGINS=*`，`allow_methods=["*"]`，`allow_headers=["*"]`，`allow_credentials=True`
- **建议**: 限制为实际需要的方法和来源

### 1.4 Tauri CSP 禁用 + Shell 权限过宽 [P0]

- **文件**: `synthetix-tauri/tauri.conf.json:24`、`synthetix-tauri/capabilities/default.json:6-11`
- **问题**: `"csp": null` 完全禁用 CSP；Shell 权限允许执行任意系统命令
- **建议**: 设置合理 CSP 策略；限定只允许执行 sidecar 二进制文件

### 1.5 LLM 提示词注入风险 [P1]

- **文件**: `src/agent/react_agent.py:132-183`、`react_agent.py:325`
- **问题**: 用户输入直接拼接到 LLM 提示词（`preset["llm_prompt"] + text`），无过滤
- **建议**: 过滤用户输入中的 `<tool_call` 标签；使用 ChatML 格式隔离用户输入

### 1.6 SSE 错误响应泄露内部信息 [P1]

- **文件**: `src/agent/react_agent.py:935`
- **问题**: `str(e)` 直接发送给前端，可能包含数据库连接串、API Key、文件路径
- **建议**: 生产环境只返回通用错误消息，详细信息仅记录日志

### 1.7 API Key 通过无认证接口暴露 [P1]

- **文件**: `src/shared/utils/config_manager.py:298-325`
- **问题**: API Key 存在数据库中，前端通过无认证的配置 API 直接读取
- **建议**: 敏感配置项返回前端时脱敏（只显示后 4 位）

### 1.8 健康检查端点暴露过多内部信息 [P1]

- **文件**: `main.py:242-296`
- **问题**: `/health` 暴露 GPU 信息、API Key 池状态、CPU/内存/磁盘等
- **建议**: `/health` 只返回 `{"status": "ok"}`，详细信息移到需认证的管理接口

### 1.9 WebSocket 缺乏认证 [P1]

- **文件**: `src/interfaces/api/ws_api.py:130-142`
- **问题**: WebSocket 端点无认证，任何人可建立连接并触发 AI 工具调用
- **建议**: accept 前校验 origin 或 token

### 1.10 日志文件可通过 HTTP 访问 [P1]

- **文件**: `src/log_config.py:87`、`src/shared/constants.py:169`
- **问题**: `LOG_DIR = "static/loginfo/"` 导致日志文件可通过 `/static/loginfo/xxx.log` 直接访问
- **建议**: 日志目录改为 `logs/`，与 static 分离

## 二、性能瓶颈（P1-P2）

### 2.1 同步阻塞调用混入异步路由 [P1]

- **文件**: `src/interfaces/api/project_api.py:155,207`、`core_nexus_client.py:236,251`
- **问题**: `ai_select_bgm` 和 `ai_generate_bgm` 在 async 路由中调用同步 `generate_response`，阻塞事件循环
- **建议**: 改用 `generate_response_async` 或 `await asyncio.to_thread()`

### 2.2 SSE 流式输出导致前端全量重渲染 [P1]

- **文件**: `synthetix-vue/src/store/modules/project.js:281-433`
- **问题**: 每个 SSE chunk 都通过 `this.messages[aiIdx].content += event.content` 追加，高频触发 Vue 响应式更新和 DOM diff
- **建议**: 使用 `requestAnimationFrame` 或 50ms debounce 合并更新；考虑 `shallowRef` 管理消息列表

### 2.3 会话持久化频率过高 [P2]

- **文件**: `src/agent/react_agent.py:598,605,613,908`
- **问题**: 每轮消息可能触发 2-3 次数据库写入
- **建议**: TAOR 循环内只做内存更新，循环结束后统一持久化一次

### 2.4 _build_messages 每轮循环重新查项目名 [P2]

- **文件**: `src/agent/react_agent.py:1434-1443`
- **问题**: 项目名不会变化，但每轮 TAOR 迭代都查数据库
- **建议**: 缓存到 `DialogState.metadata`，首次查询后复用

### 2.5 速率限制中间件效率低 [P2]

- **文件**: `src/shared/middleware/rate_limit.py:56-66`
- **问题**: `list.pop(0)` 是 O(n)；`defaultdict(list)` 无内存上限
- **建议**: 使用 `collections.deque`（`popleft()` 为 O(1)）；添加计数器上限

### 2.6 delete_temp_material 全表扫描 [P2]

- **文件**: `src/interfaces/api/project_api.py:399-419`
- **问题**: `db.query(VideoProject).all()` 加载所有项目到内存
- **建议**: 添加关联表维护素材-项目关系

### 2.7 每次会话操作创建新数据库连接 [P2]

- **文件**: `src/agent/session_manager.py:251-331`
- **问题**: 每次 `_persist_session`/`_load_from_db` 都通过 `get_db_context()` 创建新 Session
- **建议**: 使用请求级 Session 作用域或连接池

## 三、架构与代码质量（P2-P3）

### 3.1 巨型文件拆分 [P2]

| 文件 | 行数 | 建议 |
|------|------|------|
| `src/agent/tool_registry.py` | ~7920 | 按功能域拆分为 `video_tools.py`、`audio_tools.py`、`material_tools.py` 等 |
| `src/agent/react_agent.py` | ~1750 | 提取公共方法消除 process_* 系列的重复代码 |
| `src/shared/utils/core_nexus_client.py` | ~1376 | 按服务拆分为 `llm_client.py`、`tts_client.py`、`asr_client.py` |
| `src/interfaces/api/project_api.py` | ~1018 | 按子功能拆分 + 业务逻辑下沉到 Service 层 |

### 3.2 react_agent.py 逻辑高度重复 [P2]

- **文件**: `src/agent/react_agent.py:556-1282`
- **问题**: `process_message`、`process_message_stream`、`process_deep_research`、`process_plan_stream` 四个方法中会话解析、上下文合并、偏好提取等逻辑大量重复
- **建议**:
  - 提取 `_resolve_and_configure_session()` 公共方法
  - 提取 `_save_preferences_if_possible()` 偏好保存方法
  - `process_message` 内部调用 `process_message_stream` 收集结果

### 3.3 CoreNexusClient 同步/异步代码重复 [P3]

- **文件**: `src/shared/utils/core_nexus_client.py:200-726`
- **问题**: `_request` 与 `_request_async` 逻辑完全一致，仅同步/异步调用方式不同
- **建议**: 使用模板方法模式或工厂函数自动生成同步/异步方法对

### 3.4 配置系统三层冗余 [P2]

- **文件**: `src/config.py`、`src/shared/utils/config_manager.py`
- **问题**: 三套配置系统（`config.py` 模块变量 + `config_manager.py` DB 读取 + `UnifiedConfig` 类），通过 `sync_from_config_manager` 手动同步
- **建议**: 统一为 `config_manager` 的 DB + 默认值方案，使用 `pydantic-settings` 提供类型安全

### 3.5 全局单例模式不统一 [P3]

- **文件**: 多个文件
- **问题**: 6 种单例实现方式（模块级变量、`__new__`、模块级实例化等），依赖关系不清晰
- **建议**: 统一使用 FastAPI `Depends` 依赖注入或 `AppContainer` 管理所有单例

### 3.6 SSE event_generator 重复 [P3]

- **文件**: `src/interfaces/api/agent_api.py:101-184,619-643`
- **问题**: 4 个 SSE 端点的 event_generator 函数几乎完全相同
- **建议**: 提取通用 SSE 包装器函数

### 3.7 CoreNexusClient 中 print 语句残留 [P3]

- **文件**: `src/shared/utils/core_nexus_client.py:507,508,567,568`
- **问题**: 调试信息使用 `print()` 而非 `logger`
- **建议**: 替换为 `logger.debug()`

### 3.8 工具链预设中硬编码 LLM 提示词 [P3]

- **文件**: `src/agent/react_agent.py:91-116`
- **问题**: `_TOOL_CHAIN_PRESETS` 中的 `llm_prompt` 中文字符串硬编码
- **建议**: 外置到 YAML/JSON 配置文件

## 四、前端优化（P1-P3）

### 4.1 XSS 风险：手写 HTML 消毒 [P1]

- **文件**: `ChatSidebar.vue:93`、`AIClip.vue:84`、`LLMChat.vue:19`、`VL.vue:104`
- **问题**: 4 处 `v-html` 使用正则过滤 `<script>` 和 `on*` 事件，存在已知绕过手段
- **建议**: 使用 `DOMPurify` 库替代手写正则

### 4.2 timeline store 的 save 方法数据丢失 [P1]

- **文件**: `synthetix-vue/src/store/modules/timeline.js:141-142`
- **问题**: `tracks` 元素是普通对象，调用 `.toJSON()` 返回 `undefined`，保存数据永远为空
- **建议**: 改为 `JSON.parse(JSON.stringify(track))`

### 4.3 Element Plus 全量导入 [P2]

- **文件**: `synthetix-vue/src/main.js:2,47`
- **问题**: `app.use(ElementPlus)` 全量注册，即使已配置 `unplugin-vue-components` 按需加载
- **建议**: 移除 `app.use(ElementPlus)`，完全依赖自动导入

### 4.4 project store 过于庞大（810 行） [P2]

- **文件**: `synthix-vue/src/store/modules/project.js`
- **问题**: 30+ 个 state 字段、30+ 个 actions，包含项目管理、聊天、素材、BGM、方案等六大块逻辑
- **建议**: 拆分为 `useProjectStore`、`useChatStore`、`useMaterialStore`、`usePlanStore`

### 4.5 store 中存在重复定义的 generatePlan [P2]

- **文件**: `synthetix-vue/src/store/modules/project.js:634,709`
- **问题**: 同一 store 中两个 `generatePlan` 方法，后者覆盖前者，前者成为死代码
- **建议**: 删除旧版或改名消除歧义

### 4.6 store 中运行时引用不应在 state 中 [P2]

- **文件**: `synthetix-vue/src/store/modules/project.js:52,61`
- **问题**: `_saveTimers`（setTimeout ID）和 `_activeSseController`（AbortController）作为响应式 state 存储
- **建议**: 移到模块级变量或使用 `markRaw`

### 4.7 两套 HTTP 请求封装 [P2]

- **文件**: `synthetix-vue/src/utils/request.js`（fetch）vs `synthetix-vue/src/api/request.js`（axios）
- **问题**: 两套封装各自有拦截器和错误处理，行为不一致
- **建议**: 统一保留 axios 版，SSE 部分封装为独立的 `sseClient.js`

### 4.8 SSE 请求绕过 API 层 [P2]

- **文件**: `synthetix-vue/src/store/modules/project.js:310-315`
- **问题**: 直接 `fetch(API_HOST + '/api/agent/chat/stream')`，绕过拦截器
- **建议**: 封装到 `api/modules/agent.js` 中

### 4.9 audio.js API 参数传递方式不一致 [P3]

- **文件**: `synthetix-vue/src/api/modules/audio.js:6`
- **问题**: `request.get('/api/audios', params)` 应为 `request.get('/api/audios', { params })`
- **建议**: 统一修正为 `{ params }` 写法

### 4.10 组件模板重复 [P3]

- **文件**: `UnifiedEditor.vue:26-99`、`MaterialsPanel.vue:64-258`
- **问题**: 项目列表三段重复模板（~60 行）；素材表格两处重复（~80 行）
- **建议**: 抽取 `ProjectCardGroup` 和 `MaterialTable` 子组件

### 4.11 VideoStitching.vue 1275 行巨型组件 [P3]

- **文件**: `synthetix-vue/src/components/VideoStitching.vue`
- **问题**: 包含完整工作流管理，34 处硬编码中文，未经国际化
- **建议**: 拆分为 `WorkflowHeader`、`MaterialSelector`、`ClipConfigForm`、`WorkflowPreview` 等子组件

### 4.12 主题管理三处逻辑冲突 [P3]

- **文件**: `main.js:13-31`、`store/modules/system.js:36-55`、`utils/useTheme.js:8-16`
- **问题**: 主题应用逻辑在三个地方分别实现，行为不一致（`custom-dark`/`ripple` 支持）
- **建议**: 统一由 `useTheme.js` 管理，确保支持三种主题

### 4.13 国际化不完整 [P3]

- **文件**: 多个组件
- **问题**: 约 198 处中文文本未走 i18n，尤其工具弹窗组件（VideoStitching 34 处、AIClip 19 处、VoiceCloning 19 处）
- **建议**: 制定渐进式国际化计划，优先处理高频组件

### 4.14 useResizable mousemove 无节流 [P3]

- **文件**: `synthetix-vue/src/utils/useResizable.js:37-49`
- **问题**: 每次鼠标移动都触发响应式更新，高 DPI 下 60-120 次/秒
- **建议**: 使用 `requestAnimationFrame` 节流

### 4.15 MainLayout 20+ 弹窗组件同时加载 [P3]

- **文件**: `synthetix-vue/src/layouts/MainLayout.vue:440-461`
- **问题**: 所有 `el-dialog` 即使 `v-model=false` 仍创建响应式属性和组件引用，且缺少 `destroy-on-close`
- **建议**: 使用动态组件 + 单一活跃状态，或至少添加 `destroy-on-close`

## 五、构建部署与 CI/CD（P2-P3）

### 5.1 完全缺少 CI/CD [P2]

- **问题**: 无任何 CI/CD 配置，提交不自动测试，无自动构建和部署
- **建议**: 添加 GitHub Actions 配置（PR 触发 pytest + eslint，push 触发 Docker 构建）

### 5.2 PyInstaller 仅支持 Windows x86_64 [P3]

- **文件**: `build_backend.py:17`
- **问题**: 输出文件名硬编码为 `backend-x86_64-pc-windows-msvc`，缺少 `--hidden-import`
- **建议**: 使用 `platform.system()` 动态生成；添加常用隐式依赖

### 5.3 Vite 构建缺少优化配置 [P3]

- **文件**: `synthetix-vue/vite.config.js:36-37`
- **问题**: `manualChunks` 只拆分了 4 个库，Element Plus（300KB+ gzip）未进一步拆分
- **建议**: 添加 `chunkSizeWarningLimit: 500`；对 Element Plus 做更细粒度按需导入

### 5.4 Dockerfile COPY . . 可能引入敏感文件 [P2]

- **文件**: `Dockerfile:34`
- **问题**: `.dockerignore` 不够完善，未排除 `.claude/`、`.pytest_cache/` 等
- **建议**: 完善 `.dockerignore`

### 5.5 docker-compose.yml 缺少日志配置 [P3]

- **问题**: 无日志大小限制，长期运行可能占满磁盘
- **建议**: 添加 `logging` 配置（max-size: 50m, max-file: 3）

### 5.6 Docker 容器未独立运行数据库迁移 [P3]

- **问题**: 依赖 `main.py` 的 `run()` 执行迁移，改用 uvicorn 直接启动时不会迁移
- **建议**: 添加 entrypoint 脚本先执行 `alembic upgrade head`

### 5.7 .env.example 与 .env 不一致 [P3]

- **文件**: `.env.example` vs `.env`
- **问题**: `LLM_MODEL`、`MODEL_NAME`、`LLM_KEY` 等配置项未在 `.env.example` 中列出
- **建议**: 确保 `.env.example` 包含所有配置项（使用占位值）
