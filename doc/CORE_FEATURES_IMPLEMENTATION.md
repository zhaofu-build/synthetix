# FireRed-OpenStoryline 核心特性实现原理

## 项目本质

这是一个**对话式 AI 视频剪辑系统**。用户只需要用自然语言描述想要的效果（比如"帮我剪一个30秒的旅行vlog"），系统就会自动完成视频剪辑的全过程。

---

## 核心特性一：节点流水线架构

### 是什么？

把复杂的视频剪辑流程拆分成一个个独立的"处理单元"，每个单元叫做一个**节点**。就像工厂流水线一样，原材料（原始视频）经过一道道工序，最终变成成品（剪辑好的视频）。

### 有哪些节点？

```
原始视频 → 加载媒体 → 镜头分割 → 内容理解 → 筛选素材 → 分组整理
    → 生成文案 → 生成配音 → 选择配乐 → 时间线规划 → 渲染输出
```

### 每个节点如何工作？

每个节点都是独立的处理单元，包含以下信息：

- **我是谁**：节点ID和名称
- **我需要什么**：前置依赖（比如"内容理解"节点需要先完成"镜头分割"）
- **我产出什么**：处理结果的数据类型
- **我下一步可以做什么**：推荐后续节点

### 节点之间如何协作？

1. **依赖声明**：每个节点明确声明"我需要哪些前置节点的结果"
2. **自动检查**：执行前自动检查前置节点是否已完成
3. **自动补全**：如果前置节点没执行，系统会自动先执行前置节点
4. **结果传递**：前置节点的输出自动传递给当前节点作为输入

### 为什么这样设计？

- **可扩展**：添加新功能只需新增节点
- **可复用**：同一节点可被多个流程使用
- **可维护**：修改某个环节不影响其他环节
- **可追溯**：每个节点的结果都被保存，方便调试

## 核心特性二：MCP 协议

### 是什么？

MCP（Model Context Protocol）是一个**标准化的 AI 工具协议**。它让 AI 模型能够调用外部工具，就像人使用工具一样。

### 解决什么问题？

传统方式下，每个 AI 应用都要自己实现"AI 如何调用工具"的机制，互不兼容。MCP 提供了统一标准：

- AI 不需要知道工具的具体实现
- 工具不需要知道 AI 的具体模型
- 双方通过 MCP 协议通信

### 本项目如何使用 MCP？

```
┌──────────────┐         MCP协议         ┌──────────────┐
│   AI Agent   │  ◄──────────────────►  │  MCP 服务器   │
│  (大脑/决策)  │                        │  (工具提供者)  │
└──────────────┘                         └──────────────┘
                                                │
                                                ▼
                                         ┌──────────────┐
                                         │   18个节点    │
                                         │  (具体工具)   │
                                         └──────────────┘
```

**工作流程**：
1. 用户说话 → AI 理解意图
2. AI 决定调用哪个工具 → 通过 MCP 发送请求
3. MCP 服务器执行对应节点 → 返回结果
4. AI 根据结果继续决策 → 循环直到任务完成

## 核心特性三：AI Agent 决策系统

### 是什么？

Agent 是系统的"大脑"，负责理解用户意图并决定调用哪些工具。

### 核心能力

**1. 意图理解**
- 用户说"帮我剪一个快节奏的旅行视频"
- Agent 理解需要：筛选动态镜头 + 欢快配乐 + 短切镜头

**2. 工具选择**
- Agent 知道每个节点的能力
- 根据任务需求选择合适的节点组合

**3. 多轮对话**
- 不是一次性执行完所有节点
- 而是边执行边思考，根据中间结果调整策略

### 双模型架构

系统使用两个 AI 模型：

| 模型 | 用途 | 触发场景 |
|------|------|---------|
| **LLM（语言模型）** | 理解文字、生成文案、决策 | 大部分对话场景 |
| **VLM（视觉语言模型）** | 理解图片和视频内容 | 需要看视频内容的节点 |

**示例**：
- 用户说"把风景好的片段选出来" → 触发 VLM → 看视频帧 → 判断是否是风景

## 核心特性四：会话与产物管理

### 是什么？

每次用户对话都是一个**会话**，每个节点执行的结果都是一个**产物**。系统需要妥善管理这些数据。

### 产物存储

每个节点执行后，结果会被保存：

```
.storyline/.server_cache/
└── 会话ID/
    ├── meta.json          # 产物索引（记录所有产物的位置和摘要）
    ├── load_media/        # 节点1的结果
    │   └── 产物ID.json
    ├── split_shots/       # 节点2的结果
    │   └── 产物ID.json
    └── ...
```

**存储内容**：
- 节点处理结果（JSON格式）
- 媒体文件（视频片段、音频等）
- 执行摘要（供 AI 理解结果）

### 产物的作用

1. **依赖传递**：后续节点读取前置节点的产物作为输入
2. **历史回溯**：用户可以查看之前某一步的结果
3. **断点续传**：如果中途中断，可以从已有产物继续

### 会话生命周期

- **创建**：用户开始对话时创建新会话
- **活跃**：持续交互期间保持
- **过期清理**：默认保留3天，自动清理过期会话

## 核心特性五：拦截器机制

### 是什么？

拦截器是夹在"AI 调用工具"和"工具执行"之间的中间层，可以在工具执行前后做额外处理。

### 为什么要拦截器？

有些通用逻辑不适合写在每个节点里，比如：
- 自动注入媒体文件路径
- 自动执行缺失的前置节点
- 统一保存执行结果
- 注入 API 密钥等配置

### 本项目的拦截器

**前置拦截器**（执行前）：

1. **媒体注入拦截器**
   - 检测到"加载媒体"节点时
   - 自动扫描用户上传的媒体目录
   - 把媒体文件信息注入到节点输入中

2. **依赖检查拦截器**
   - 检测节点是否缺少前置依赖
   - 如果缺少，自动递归执行缺失的前置节点
   - 把前置节点的输出注入到当前节点输入

3. **配置注入拦截器**
   - 自动注入 TTS 配置（语音合成参数）
   - 自动注入 Pexels API 密钥（素材搜索）

**后置拦截器**（执行后）：

1. **结果保存拦截器**
   - 节点执行完成后自动保存结果
   - 更新产物索引
   - 格式化返回给 AI 的摘要信息

### 执行流程

```
AI 调用节点
    │
    ▼
┌─────────────────┐
│  前置拦截器链    │  ← 注入媒体、检查依赖、注入配置
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   节点执行       │  ← 实际业务逻辑
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  后置拦截器链    │  ← 保存结果、格式化输出
└────────┬────────┘
         │
         ▼
    返回给 AI
```

## 核心特性六：技能系统

### 是什么？

技能是**可复用的剪辑工作流模板**，把常用的剪辑流程打包成技能，下次直接调用。

### 为什么需要技能？

- 避免每次都从零开始描述需求
- 把最佳实践固化下来
- 让 AI 学习用户的剪辑风格

### 技能的形态

每个技能是一个 Markdown 文件，描述了：
- 技能名称和用途
- 适用场景
- 执行步骤
- 参数说明

```
.storyline/skills/
├── speech_rough_cut_skill/     # 口播视频粗剪
│   └── SKILL.md
├── subtitle_imitation_skill/   # 字幕风格仿写
│   └── SKILL.md
└── create_profile_style_skill/ # 个人风格生成
    └── SKILL.md
```

### 技能如何工作？

1. **加载**：系统启动时扫描技能目录，加载所有技能
2. **转换**：把 Markdown 技能转换为 AI 可调用的工具
3. **使用**：AI 根据用户意图选择合适的技能执行
4. **创建**：AI 可以根据对话创建新技能并保存

---

## 核心特性七：配置管理

### 是什么？

用配置文件（config.toml）管理系统的所有参数，而不是硬编码在代码里。

### 配置内容

| 配置项 | 内容 |
|--------|------|
| **LLM/VLM** | 模型名称、API地址、密钥、超时时间 |
| **项目路径** | 媒体目录、输出目录、缓存目录 |
| **MCP服务器** | 端口、协议类型、超时设置 |
| **节点参数** | 镜头分割阈值、采样帧率、BGM参数等 |
| **技能** | 技能目录位置 |

### 配置特点

1. **路径自动解析**：相对路径会自动基于配置文件位置解析
2. **类型校验**：启动时自动检查配置格式是否正确
3. **热更新**：修改配置后重启服务即可生效

## 整体工作流程

### 用户视角

```
1. 用户上传视频素材
2. 用户说："帮我剪一个30秒的旅行vlog，风格要欢快"
3. 系统自动处理...
4. 输出最终视频
```

### 系统内部流程

```
1. 接收用户请求
   │
   ▼
2. AI Agent 分析意图
   - 理解需求：旅行vlog、30秒、欢快风格
   - 规划步骤：加载→分割→理解→筛选→配乐→渲染
   │
   ▼
3. 逐步执行节点（通过 MCP 调用）
   │
   ├─► 加载媒体节点
   │   └─► 拦截器自动扫描媒体目录
   │
   ├─► 镜头分割节点
   │   └─► 使用 TransNetV2 模型检测镜头边界
   │
   ├─► 内容理解节点
   │   └─► 调用 VLM 分析每个镜头内容
   │
   ├─► 筛选素材节点
   │   └─► 根据用户需求筛选合适片段
   │
   ├─► 生成文案节点
   │   └─► 调用 LLM 生成旁白文字
   │
   ├─► 生成配音节点
   │   └─► 调用 TTS 服务生成语音
   │
   ├─► 选择配乐节点
   │   └─► 分析 BGM 节拍，匹配欢快风格
   │
   ├─► 时间线规划节点
   │   └─► 计算每个片段的起止时间
   │
   └─► 渲染输出节点
       └─► 调用 FFmpeg 合成最终视频
   │
   ▼
4. 返回结果给用户
```

## 关键设计思想总结

| 设计思想 | 具体体现 |
|----------|----------|
| **模块化** | 每个功能拆分成独立节点 |
| **标准化** | 使用 MCP 协议统一工具接口 |
| **智能化** | AI 自动理解意图、规划步骤 |
| **自动化** | 拦截器自动处理依赖和配置 |
| **可持久化** | 产物存储支持断点续传 |
| **可扩展** | 技能系统支持自定义工作流 |
| **可配置** | 所有参数通过配置文件管理 |

---

## 与普通视频剪辑软件的区别

| 对比项 | 普通软件 | 本系统 |
|--------|----------|--------|
| 操作方式 | 手动拖拽、点击 | 自然语言对话 |
| 技能门槛 | 需要学习软件操作 | 无需专业技能 |
| 效率 | 逐帧调整 | 自动批量处理 |
| 创意支持 | 依赖用户经验 | AI 提供建议 |
| 可复用性 | 手动重复操作 | 技能一键复用 |

## 技术栈一览

| 层次 | 技术 |
|------|------|
| **AI 框架** | LangChain（Agent 框架）|
| **工具协议** | MCP（Model Context Protocol）|
| **Web 服务** | FastAPI + Uvicorn |
| **视频处理** | MoviePy + FFmpeg + PyAV |
| **镜头分割** | TransNetV2（深度学习模型）|
| **语音识别** | FunASR |
| **文本嵌入** | Sentence-Transformers |
| **向量检索** | FAISS |
| **配置管理** | Pydantic + TOML |
| **技能管理** | SkillKit |
