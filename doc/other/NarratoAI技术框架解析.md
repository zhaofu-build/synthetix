## 项目概述

**NarratoAI** 是一款基于AI大模型的自动化视频创作工具，旨在为内容创作者提供从视频分析、脚本生成到视频剪辑和配音的一站式解决方案。该项目采用微服务架构设计，将视频创作流程拆分为多个独立模块，通过标准化接口实现协同工作。**通过AI技术，它能够将原本需要数小时的人工视频制作流程缩短至15-20分钟**，极大提升了创作效率。

项目主要面向以下用户群体：
- 个人自媒体创作者
- 小型视频制作团队
- 教育机构
- 电商运营团队
- 新闻媒体机构

**核心价值主张**：
- **零门槛操作**：无需专业视频编辑技能
- **全流程自动化**：从视频分析到最终成片的完整流程
- **多平台适配**：支持抖音、B站、YouTube等主流平台
- **高质量输出**：生成专业水准的解说视频

## 技术架构

![NarratoAI架构图]

### 架构设计

NarratoAI采用**微服务架构**，将视频创作流程拆分为独立功能模块，通过标准化接口实现协同工作。这种架构设计具有以下优势：

1. **模块独立升级**：各组件可独立更新，不影响整体系统运行
2. **灵活扩展性**：支持二次开发和功能扩展
3. **高可用性**：单个模块故障不影响其他组件运行
4. **资源隔离**：不同模块可配置不同资源限制

### 核心组件

系统主要包含以下四大核心组件：

| 组件名称 | 技术栈 | 功能描述 |
|---------|-------|---------|
| WebUI交互层 | Streamlit + Python 3.10+ | 提供用户界面，支持参数配置、任务监控和结果预览 |
| LLM模型服务层 | FastAPI + 多种大模型接口 | 封装和管理大语言模型API调用，包括Gemini、Qwen、DeepSeek等 |
| 媒体处理工具链 | FFmpeg + Whisper + ImageMagick | 负责视频关键帧提取、音频转录、图像处理等媒体相关操作 |
| 视频脚本生成模块 | 自定义Python服务 | 基于视频内容和LLM输出生成结构化视频脚本 |

数据流路径：用户通过WebUI提交任务 → 媒体处理工具链提取关键帧和音频 → LLM模型服务层分析内容并生成解说文本 → 视频脚本生成模块创建完整视频脚本 → WebUI展示结果并支持导出

### 技术依赖

项目依赖以下关键技术栈：

- **Python 3.10+**：核心开发语言
- **FastAPI**：后端API服务框架
- **Streamlit**：WebUI框架，提供交互式界面
- **Docker**：容器化部署方案
- **FFmpeg**：视频处理核心工具，用于关键帧提取和视频合成
- **Whisper**：语音识别模型，用于生成字幕
- **ImageMagick**：图像处理工具，用于关键帧预处理
- **大型语言模型API**：支持Gemini、Qwen、DeepSeek等多款模型

## 核心功能模块

### 1. 视频分析与关键帧抽取模块

**功能描述**：自动识别视频中的关键场景和画面特征，提取代表性关键帧

**技术实现**：
- 使用FFmpeg的`-vf select='gt(scene,0.3)'`过滤器检测场景切换点
- 支持两种关键帧抽取策略：
  - 固定间隔抽取（适合纪录片）：`-vf "fps=1/2"`（每2秒抽一帧）
  - 场景切换点抽取（适合剧情类影视解说）：`select='gt(scene,0.25)'`
- 可配置场景切换检测阈值（0.25-0.35之间）
- 自动提取关键帧并存储为JPEG序列

### 2. 语音识别与字幕生成模块

**功能描述**：从视频中提取音频并生成时间戳字幕（SRT格式）

**技术实现**：
- 基于Whisper语音识别模型进行音频转录
- 支持多语言识别（中、英、日等）
- 字幕清洗流程：
  - 过滤时长小于0.5秒的片段
  - 去除纯标点或空文本行
  - 合并间隔小于0.2秒的相邻片段
  - 清洗后SRT条目通常减少15%-30%
- 支持不同模型大小选择（base/medium/large），中文内容推荐使用medium模型（约1.4GB）

### 3. AI解说文案生成模块

**功能描述**：基于视频内容自动生成逻辑连贯、符合平台风格的解说文案

**技术实现**：
- 支持多种大语言模型（Gemini、Qwen2-VL、DeepSeek等）
- 模型选择策略：
  - Gemini：稳定性好，适合通用场景
  - DeepSeek：成本低，适合批量生产
  - Qwen2-VL：视频理解能力强，适合复杂场景
- 输入数据结构：
  ```json
  {
    "timestamp": "00:00:05",
    "video_description": "关键帧图像描述",
    "audio_transcript": "对应时间点的语音转录"
  }
  ```
- 输出数据结构：
  ```json
  {
    "clips": [
      {
        "start": "00:00:05",
        "end": "00:00:15",
        "source_video": "video1.mp4",
        "narration": "解说文本",
        "audio_path": "生成音频路径",
        "subtitle": "字幕文本"
      }
    ],
    "global_settings": {
      "video_ratio": "9:16",
      "tts_engine": "qwen",
      "dubbing": "male"
    }
  }
  ```
- 通过提示词工程确保输出格式符合规范

### 4. 智能配音与字幕合成模块

**功能描述**：将解说文本转换为语音并添加到视频中，同时生成可视化字幕

**技术实现**：
- 支持多种TTS引擎（Microsoft TTS、腾讯云TTS、IndexTTS2等）
- 配音参数配置：
  - 语速控制（0.8-1.2倍速）
  - 音色选择（男声/女声/特定风格）
  - 情感强度调节
- 字幕样式自定义：
  - 字体选择（如Microsoft YaHei Bold）
  - 颜色和大小调整
  - 位置设置（底部/中部）
  - 背景透明度控制
- 支持多平台字幕风格预设（抖音、B站等）

### 5. 视频剪辑与合成模块

**功能描述**：根据生成的脚本自动剪辑视频片段并合成最终成片

**技术实现**：
- 使用FFmpeg进行视频合成：
  ```bash
  ffmpeg -f concat -safe 0 -i clip_list.txt -i generated_audio.mp3 -vf "subtitles=script.srt" -c:v libx264 -c:a aac output.mp4
  ```
- 支持视频比例调整（9:16竖屏、16:9横屏等）
- 支持背景音乐添加和音量平衡
- 支持视频转场效果添加
- 支持导出剪映草稿文件（便于专业编辑）

### 6. 短剧混剪模块（高级功能）

**功能描述**：自动识别多部视频中的关键片段，按逻辑顺序混剪成连贯短剧

**技术实现**：
- **人脸匹配**：
  - 使用OpenCV的dnn模块加载预训练模型
  - 提取人脸特征向量（128维）
  - 存储到缓存数据库（如SQLite）
- **口播匹配**：
  - 将解说文本关键词提取
  - 与视频片段特征向量计算余弦相似度
  - 选择匹配度最高的片段
- **钩子优化**：
  - 自动在视频开头插入高吸引力片段（前3秒）
  - 优化视频开头的完播率

## 视频处理工作流

![视频处理工作流]

### 1. 字幕提取阶段

**输入**：原始视频文件（MP4格式）
**输出**：SRT字幕文件
**工具**：FFmpeg + Whisper
**处理步骤**：
1. 使用FFmpeg分离视频音轨：
   ```bash
   ffmpeg -i input.mp4 -acodec copy audio.wav
   ```
2. 调用Whisper进行语音识别：
   ```bash
   whisper audio.wav --language zh --model medium --output_format srt --output_dir ./
   ```
3. 清洗SRT文件（去除短片段、合并相邻片段等）

### 2. 关键帧抽取阶段

**输入**：原始视频文件
**输出**：关键帧JPEG序列
**工具**：FFmpeg
**处理步骤**：
1. 根据配置选择关键帧抽取策略（固定间隔/场景切换点）
2. 提取关键帧并保存：
   ```bash
   ffmpeg -i input.mp4 -vf "select='gt(scene,0.3)'",showinfo -vsync vfr -q:v 2 frames/scene_%04d.jpg
   ```
3. 关键帧预处理（调整大小、裁剪等）

### 3. 视频内容分析阶段

**输入**：关键帧图像、SRT字幕
**输出**：视频内容分析结果
**工具**：LLM视觉模型（如Qwen2-VL）
**处理步骤**：
1. 将关键帧和对应时间戳的字幕组织为LLM输入格式
2. 调用视觉模型API进行分析
3. 提取视频场景描述、关键元素、情感基调等信息

### 4. 解说文案生成阶段

**输入**：视频内容分析结果、用户配置参数
**输出**：JSON格式的解说脚本
**工具**：LLM文本模型（如Gemini、DeepSeek）
**处理步骤**：
1. 根据配置选择文案生成模型
2. 构建LLM提示词，包含视频主题描述、风格要求等
3. 调用LLM API生成解说文本
4. 生成结构化JSON脚本，包含时间戳、解说内容、字幕等信息

### 5. 配音合成阶段

**输入**：解说脚本JSON
**输出**：生成的音频文件（MP3格式）
**工具**：TTS引擎
**处理步骤**：
1. 根据配置选择TTS引擎（如Microsoft TTS）
2. 将解说文本转换为语音
3. 合成音频并添加背景音乐（可选）
4. 处理音频格式（转换为16kHz采样率等）

### 6. 视频剪辑与合成阶段

**输入**：原始视频、解说脚本JSON、生成音频
**输出**：最终解说视频
**工具**：FFmpeg
**处理步骤**：
1. 根据脚本中的时间戳提取视频片段
2. 合并视频片段，添加转场效果
3. 叠加生成的字幕
4. 混合解说音频和背景音乐
5. 编码输出最终视频文件

### 7. 短剧混剪工作流（高级）

**输入**：多部视频文件、混剪主题描述
**输出**：连贯的短剧混剪视频
**处理步骤**：
1. 对多部视频进行批量分析，提取关键帧和字幕
2. 通过LLM生成混剪脚本，包含情节逻辑和时间轴
3. 人脸匹配算法识别相同角色
4. 口播内容与视频片段智能匹配
5. 优化视频开头钩子，提升完播率
6. 合成最终混剪视频

## 部署指南

### 环境要求

#### 最低配置
- **CPU**：4核或以上
- **内存**：8GB或以上
- **存储**：SSD（推荐），至少预留5GB空间
- **操作系统**：Windows 10/macOS 11.0+/Linux
- **网络**：稳定互联网连接（用于API调用）
- **硬件要求**：**无需GPU**，计算在云端完成

#### 推荐配置
- **CPU**：8核或以上
- **内存**：16GB或以上
- **存储**：PCIe 4.0及以上SSD（处理速度提升30%+）
- **操作系统**：Windows 11/macOS 12+/Linux（最新发行版）
- **并发处理**：建议使用NAS或服务器部署以支持批量处理

### 安装步骤

#### 1. Docker部署（推荐）

**步骤1**：安装Docker和Docker Compose
```bash
# Ubuntu/Debian
sudo apt-get update
sudo apt-get install docker.io docker-compose

# macOS
# 通过Homebrew安装
brew install docker docker-compose
```

**步骤2**：克隆项目仓库
```bash
git clone https://github.com/linyqh/NarratoAI.git
cd NarratoAI
```

**步骤3**：配置API密钥
```bash
cp config.example.toml config.toml
```
在`config.toml`中填写大模型API密钥：
```toml
[gemini]
api_key = "your_gemma_api_key"  # 从Google AI Studio获取

[local]
# 本地工具路径配置
形象路径 = "/usr/local/bin/imagemagick"
```

**步骤4**：启动服务
```bash
docker compose up -d
```

**步骤5**：访问WebUI
```
http://localhost:8501
```

**步骤6**：访问API文档（可选）
```
http://localhost:8080/docs
```

#### 2. Windows本地部署（无Docker）

**步骤1**：安装必要组件
```powershell
# 使用winget安装Python、Git和FFmpeg
winget install Python.Python.3.10
winget install Git.Git
winget install Gyan.FFmpeg

# 安装ImageMagick
# 下载并安装：https://imagemagick.org/archive/binaries/ImageMagick-7.1.1-40-Q16-x64-static.exe
```

**步骤2**：配置系统环境变量
```powershell
# 设置ImageMagick路径
$env:PATH += ";C:\Program Files (x86)\ImageMagick-7.1.1-Q16-x64\"

# 设置代理（国内用户需要）
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
```

**步骤3**：创建虚拟环境并安装依赖
```powershell
# 创建虚拟环境
python -m venv .venv

# 激活虚拟环境
.\.venv\Scripts\activate

# 安装依赖（推荐使用清华源）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**步骤4**：获取模型API密钥
- Gemini：访问Google AI Studio获取
- Qwen：访问阿里云通义千问平台获取
- DeepSeek：访问DeepSeek官网获取

**步骤5**：启动WebUI
```powershell
streamlit run ./webui Main.py --browser.serverAddress=127.0.0.1 --server.enableCORS=True --browser.gatherUsageStats=False
```

## 最佳实践与性能优化

### 部署优化策略

#### 1. Docker资源限制配置

在`docker-compose.yml`中设置资源限制，确保系统稳定运行：
```yaml
services:
  narratoai-webui:
    image: linyqh/narratoai:latest
    deploy:
      resources:
        limits:
          cpus: '4'   # 最大使用4个CPU核心
          memory: 16G  # 最大使用16GB内存
        reservations:
          cpus: '2'   # 建议至少保留2个CPU核心
          memory: 8G  # 建议至少保留8GB内存
    ports:
      - "8501:8501"
      - "8080:8080"
    volumes:
      - ./resource:/NarratoAI/resource
      - ./output:/NarratoAI/output
      - ./config.toml:/NarratoAI/config.toml
    restart: unless-stopped
```

#### 2. 本地部署优化

- **使用虚拟环境**：避免全局包冲突
- **依赖包管理**：定期更新`requirements.txt`中的依赖
- **缓存清理**：使用WebUI的"一键清理缓存"功能释放磁盘空间
- **配置文件备份**：修改配置前备份原文件
- **日志监控**：通过`nvidia-smi`（GPU）或`htop`（CPU）监控资源使用情况

### 性能优化策略

#### 1. 硬件优化

- **内存扩展**：增加内存至16GB可显著提升视频处理速度
- **SSD存储**：使用SSD存储视频和缓存文件，减少I/O瓶颈，提升处理速度30%+
- **多线程处理**：配置`batch_size`参数（建议4-8）实现多视频并行处理
- **代理配置**：确保LLM API调用的网络稳定性，配置可靠的代理服务器

#### 2. 参数优化

- **关键帧抽取**：根据视频类型调整`scene`阈值（纪录片可调高至0.4，剧情片调低至0.25）
- **Whisper模型选择**：中文内容推荐使用medium模型，平衡识别准确率和处理速度
- **视频编码器选择**：
  - 最高兼容性：`libx264`
  - NVIDIA GPU加速：`h264_nvenc`
  - macOS GPU加速：`h264_videotoolbox`
- **分辨率调整**：
  - 4K（2160p）：最高质量，处理时间最长
  - Full HD（1080p）：推荐配置，平衡质量与速度
  - HD（720p）：批量处理推荐配置，速度最快

#### 3. 工作流优化

- **批量处理**：将多个视频放入`resource/videos`目录，一键生成多个解说视频
- **模板复用**：为常用内容类型创建模板脚本，减少重复配置
- **参数预设**：在`config.toml`中为不同平台预设参数组合（如抖音、B站等）
- **错误处理**：关键步骤配置`llm_max_retries`（建议3次）应对API调用失败
- **任务队列**：Docker部署支持多任务队列，避免同时处理过多视频导致系统崩溃

#### 4. API调用优化

- **配额管理**：根据Gemini等模型的每日配额合理安排任务
  - Pro订阅：每日最多3次视频生成
  - Ultra订阅：每日最多5次视频生成
- **成本控制**：
  - 短视频：使用DeepSeek等成本较低的模型
  - 高质量内容：使用Gemini等高质量模型
- **预估消耗**：使用`narrator-ai-cli user balance`查看API调用点数余额
- **子账号体系**：MCN团队可使用子账号隔离不同创作者的API配额
