# 05 - 记忆与上下文管理

## 概述

记忆系统是 Claude Code 实现长期智能和持续学习能力的核心。采用**三层记忆架构**和**五级上下文压缩**机制，系统性解决大模型上下文窗口限制。核心挑战在于：模型上下文窗口有限，但开发任务可能持续数小时甚至跨会话。

## 三层记忆架构

### 架构总览

```
┌─────────────────────────────────────────────┐
│              短期记忆（Session Memory）         │
│          内存缓存 · LRU 淘汰 · 当前会话          │
├─────────────────────────────────────────────┤
│              工作记忆（Task Memory）            │
│        临时存储 · fork 隔离 · 当前任务上下文       │
├─────────────────────────────────────────────┤
│              长期记忆（Project Memory）          │
│      .claude/memdir · Sonnet 相关性 · 跨会话     │
└─────────────────────────────────────────────┘
```

### 1. 短期记忆（Session Memory）

| 属性 | 说明 |
|------|------|
| 存储位置 | 内存缓存 |
| 淘汰策略 | LRU（最近最少使用） |
| 管理类 | `MemoryCache` |
| 生命周期 | 单次会话 |
| 内容 | 当前会话交互记录、工具调用结果 |

**作用：** 保持当前会话的连贯性，使 Agent 能引用之前的对话内容。

### 2. 工作记忆（Task Memory）

| 属性 | 说明 |
|------|------|
| 存储位置 | 临时内存 |
| 隔离方式 | `MemoryManager.fork()` |
| 生命周期 | 单个任务 |
| 内容 | 当前任务上下文、子任务状态 |

**隔离设计：** 通过 `fork()` 方法为子任务创建独立的记忆空间，防止不同任务间的上下文污染。子任务完成后通过 `merge()` 将结果合并回主记忆。

```typescript
class MemoryManager {
  // 为子任务 fork 独立记忆
  fork(taskId: string): MemoryManager {
    const childMemory = new MemoryManager();
    childMemory.parent = this;
    childMemory.taskId = taskId;
    return childMemory;
  }

  // 子任务完成后合并结果
  merge(childMemory: MemoryManager): void {
    this.taskResults.set(childMemory.taskId, childMemory.getSummary());
  }
}
```

### 3. 长期记忆（Project Memory）

| 属性 | 说明 |
|------|------|
| 存储位置 | `.claude/memdir` 目录（持久化） |
| 相关性计算 | Sonnet 模型动态计算 |
| 生命周期 | 跨会话持久保存 |
| 内容 | 项目级知识库、历史决策记录 |

**跨会话召回：** 项目级知识在不同会话间共享，形成持久的项目知识库。

### 自动记忆提取

系统通过后台子代理的**两回合读写策略**自动提取有价值的记忆：

1. **读回合**：子代理扫描当前上下文，识别值得记忆的信息
2. **写回合**：将提取的记忆写入长期存储
3. **互斥设计**：确保记忆提取的准确性和一致性，避免并发冲突

## 五级上下文压缩

`snipCompression` 算法根据对话长度自动触发不同级别压缩，核心目标是**保留语义连续性**的前提下减少 token 占用。

### 压缩级别

| 级别 | 策略 | 触发条件 | 说明 |
|------|------|----------|------|
| **Level 1** | 轻度截断 | 上下文接近限制 | 保留用户指令和关键工具输出 |
| **Level 2** | 深度截断 | 上下文进一步增长 | 截断冗长的工具输出，保留关键摘要 |
| **Level 3** | 摘要生成 | 上下文显著超限 | 使用 **Sonnet 模型**压缩对话历史为摘要 |
| **Level 4** | MCP 资源引用 | 上下文严重超限 | 大文件替换为 `@file(id)` 占位符 |
| **Level 5** | 激进压缩 | 上下文极限 | 组合所有策略，最小化上下文占用 |

### 压缩流程

```
对话持续进行 → 上下文不断增长
  ↓
计算当前上下文 token 数
  ↓
未超限 → 直接返回（不压缩）
  ↓
超限 → Level 1-2：Snip 截断
  ↓
仍超限 → Level 3：Sonnet 模型生成摘要
  ↓
仍超限 → Level 4-5：MCP 资源引用 + 激进压缩
```

### 关键设计：保留语义连续性

压缩不是简单的截断，而是保留语义关键点：

- **用户指令**：始终保留，不做压缩
- **关键工具输出**：保留摘要，移除冗余
- **Agent 中间推理**：优先压缩
- **错误信息**：保留关键错误，移除堆栈追踪的重复部分

## 分层摘要与上下文折叠

### 三层上下文结构

```
┌─────────────────────────────────┐
│ 核心层（不折叠）                    │
│   system_prompt + user_input     │
│   始终完整保留                     │
├─────────────────────────────────┤
│ 压缩层（摘要）                     │
│   tool_result + agent_message    │
│   生成摘要保留关键信息              │
├─────────────────────────────────┤
│ 临时层（截断）                     │
│   最近消息保留关键几行              │
│   较早消息可能完全截断              │
└─────────────────────────────────┘
```

### 基于信息熵的优先级

使用信息熵评估上下文重要性，决定压缩优先级：

```typescript
function calculateContextEntropy(context: string): number {
  // 计算信息熵
  // 低熵 = 高信息密度（结构化数据、代码）→ 保留更多
  // 高熵 = 低信息密度（重复内容、空白）→ 可更激进压缩
  const entropy = -context.split('').filter(c => c !== ' ')
    .reduce((count, char) => {
      count[char] = (count[char] || 0) + 1;
      return count;
    }, {} as Record<string, number>)
    .map((count, char) => {
      const prob = count / context.length;
      return prob * Math.log2(prob);
    })
    .reduce((sum, probLog) => sum + probLog, 0);
  return entropy;
}
```

### 动态清理机制

```
1. 计算当前上下文 token 数
2. 未超限 → 直接返回
3. 超限 → 分层摘要（核心层/压缩层/临时层）
4. 仍超限 → 基于熵值的反应式压缩（优先压缩高熵内容）
5. 仍超限 → 上下文折叠（将早期对话折叠为极简摘要）
```

## 检查点机制

- 重要操作前创建检查点（`Checkpoint` 工具）
- 检查点包含完整的上下文快照
- 支持回滚到之前的检查点状态
- 用于长时间任务的容错恢复

## 上下文隔离

| 隔离场景 | 实现方式 |
|----------|----------|
| 不同 Agent | 拥有独立记忆空间 |
| 子 Agent | 仅加载项目配置和 MCP 数据 |
| 主/子 Agent | 子 Agent **不继承**主 Agent 对话历史 |
| 工作记忆 | `MemoryManager.fork()` 隔离 |

**目的：** 防止上下文污染，确保每个 Agent 基于干净的上下文独立工作。

## 实际效果

使用户可以在一个会话中连续工作数小时而不丢失关键信息。`snipCompression` 算法在对话变长时自动截断历史消息但保留语义关键点，解决了 Claude API 上下文窗口限制问题。
