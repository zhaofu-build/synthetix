# 06 - 权限与安全系统

## 设计哲学

**谨慎优先（Prudence First）** — 通过多层次权限控制平衡安全性与用户体验。Claude Code 的安全设计不是单一防线，而是**纵深防御** — 从配置、验证、沙箱到审计，层层递进。

## 三层权限配置文件

| 层级 | 路径 | 作用域 | 是否提交 Git |
|------|------|--------|-------------|
| 全局配置 | `~/.claude/settings.json` | 所有项目 | 否 |
| 项目级配置 | `<项目>/.claude/settings.json` | 当前项目，团队共享 | 是 |
| 本地配置 | `<项目>/.claude/settings.local.json` | 当前项目，个人专属 | 否（.gitignore） |

**优先级：** 本地 > 项目级 > 全局

**关键规则：** 任何层级的 `deny` 规则具有**最高优先级**，不会被更高层级的 `allow` 覆盖。这确保了安全策略的不可绕过性。

## 三层过滤逻辑

工具调用的权限决策按以下顺序逐层过滤：

```
deny（直接拒绝，无弹窗）→ ask（弹窗询问用户）→ allow（自动执行）→ 默认行为
```

| 过滤结果 | 行为 | 示例 |
|----------|------|------|
| `deny` | 直接拒绝，不弹窗 | 读取 `.env`、执行 `rm -rf` |
| `ask` | 需手动确认 | `git push`、`npm install` |
| `allow` | 自动执行 | `git status`、`vite build` |

### 配置示例

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf *)",
      "Read(.env)",
      "Write(.env)"
    ],
    "allow": [
      "Bash(git status)",
      "Bash(npm run build)",
      "Read(**)"
    ],
    "ask": [
      "Bash(git push*)",
      "Bash(npm install*)"
    ]
  }
}
```

## 六级权限验证链

每个工具调用在执行前必须通过六级验证：

```
1. 用户身份认证（OAuth / 本地会话）
   ↓
2. 工具白名单匹配（仅允许注册工具）
   ↓
3. 文件路径沙箱限制（PathSanitizer 过滤）
   ↓
4. 命令黑名单过滤（如 Bash 禁用 rm -rf）
   ↓
5. 操作风险评估（动态风险等级，高危需管理员审批）
   ↓
6. 执行审计日志（记录操作并触发告警）
```

### 第 1 级：用户身份认证

- OAuth 认证或本地会话 Token
- 确保调用者身份可信

### 第 2 级：工具白名单

- 只有在 `ToolManager` 中注册的工具才能被调用
- 模型无法调用未注册的工具（防止提示注入攻击）

### 第 3 级：路径沙箱

```typescript
class PathSanitizer {
  sanitize(filePath: string): string {
    // 解析符号链接和 .. 等相对路径
    const resolved = path.resolve(filePath);
    // 检查是否在允许的目录范围内
    if (!this.allowedPaths.some(allowed => resolved.startsWith(allowed))) {
      throw new Error('路径超出沙箱范围');
    }
    return resolved;
  }
}
```

### 第 4 级：命令黑名单

- Bash 工具禁用 `rm -rf`、`mkfs` 等破坏性命令
- 模式匹配过滤危险命令模式

### 第 5 级：操作风险评估

- 动态计算操作风险等级
- 高危操作（如修改生产配置）需额外审批

### 第 6 级：执行审计日志

- 记录所有工具调用的参数和结果
- 高危操作触发告警通知

## 四层决策管道

`DecisionPipeline` 将权限决策结构化为四步管道：

```
参数校验 → 风险分析 → 用户授权 → 审计日志
```

1. **参数校验**：Zod Schema 验证输入参数类型和范围
2. **风险分析**：基于操作类型和上下文动态评估风险
3. **用户授权**：根据权限模式决定是否弹窗确认
4. **审计日志**：记录决策过程和结果

## OS 层安全隔离

### macOS 应用沙盒（Seatbelt）

通过 macOS Seatbelt 机制（`sandbox-exec`）对 Claude Code 进行系统级隔离：

```typescript
// 沙盒配置示例
const sandboxProfile = {
  // 文件系统：仅允许白名单路径
  filesystem: {
    allow: ['/tmp/claude-runtime', projectRoot],
    deny: ['~/.ssh', '~/.gnupg']
  },
  // 网络：Unix 域套接字 + 域名限制
  network: {
    allow: ['api.anthropic.com', '*.mcp-server.com'],
    deny: ['*']
  }
};
```

**效果：** 沙盒使权限提示减少 **84%**（因为沙盒内操作已默认安全）。

### 进程隔离

| 保护机制 | 参数 | 说明 |
|----------|------|------|
| Bun 子进程 | `--sanitized` | 启用资源限制 |
| 超时保护 | **120 秒** | 强制终止长时间阻塞命令 |
| 输出截断 | **50,000 字节** | 防止工具输出溢出上下文 |

## 防蒸馏机制

防止模型输出被用于训练竞品模型的保护措施。

### 核心实现

```typescript
class AntiDistillationGuard {
  async augmentPrompt(prompt, tools) {
    if (process.env.ANTI_DISTILLATION_CC) {
      // 1. 随机选择工具生成虚假描述
      const randomTools = tools.shuffle().slice(3);
      const fakeDefinitions = randomTools.map(tool => ({
        name: tool.name,
        description: generateFakeDescription(),
        params: generateFakeParams()
      }));
      // 2. 将虚假工具定义注入提示词
      prompt = injectFakeDefinitions(prompt, fakeDefinitions);
    }
    return prompt;
  }
}
```

### 防护层级

| 机制 | 说明 |
|------|------|
| 虚假工具注入 | 每次会话随机生成虚假工具描述，混淆真实工具定义 |
| 客户端验证 | 通过 `cch_Attestation` 验证客户端合法性 |
| 上下文隔离 | 子 Agent 不继承主 Agent 对话历史 |
| 签名校验 | MCP 连接建立时验证服务器签名 |

## 循环检测

防止 Agent 陷入无效循环，三级检测机制：

### 1. 工具调用重复检测（快速检测）

- **规则**：连续 **5 次**相同工具 + 相同参数
- **判定**：循环
- **处理**：强制跳出循环，提示用户

### 2. 内容重复检测（中等检测）

- **方法**：50 字符滑动窗口哈希
- **规则**：短距离内重复 **10 次**
- **判定**：循环
- **处理**：压缩重复内容后继续

### 3. LLM 智能检测（深度检测）

- **触发**：上下文 > **30 条**消息时
- **方法**：调用模型判断当前行为是否构成循环
- **优势**：能识别语义层面的循环（不完全相同的参数但等效的操作）

## 权限模式

通过 `--permission-mode` 启动参数或会话中切换：

| 模式 | 行为 | 适用场景 | 安全等级 |
|------|------|----------|----------|
| `default` | 所有操作需确认 | 首次使用、学习阶段 | 最高 |
| `acceptEdits` | 文件编辑自动授权，命令执行需确认 | 日常开发 | 中等 |
| `plan` | 仅规划，不执行任何修改 | 方案设计 | 高（只读） |
| `bypassPermissions` | 跳过所有弹窗 | CI/CD 自动化环境 | 最低 |

支持 `--allowedTools` 参数预授权工具列表，免确认直接执行。

